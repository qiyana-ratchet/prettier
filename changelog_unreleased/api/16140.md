#### Restrict range formatting to the user's selection (#16140 by @qiyana-ratchet)

When formatting with `--range-start` / `--range-end`, Prettier expands the range to enclosing statement/declaration boundaries (so the substring is parseable) and then formats that whole expanded region. Code outside the user's original range could end up reformatted as a side effect.

Now, when the calculated range exceeds the user's range, a line-level diff is used to keep only those formatting changes whose original lines overlap the user's selection; the rest of the range is left untouched. Line-level diffing ensures related changes on the same line — e.g. a matching pair of opening / closing quotes — are always applied together.

<!-- prettier-ignore -->
```jsx
// Input (range covers only `reformatThis`):
class F {
  reformatThis(  ){
    return    1    ;
  }

  dontTouchThis(  ){
    return    2    ;
  }
}

// Prettier stable
class F {
  reformatThis() {
    return 1;
  }

  dontTouchThis() {
    return 2;
  }
}

// Prettier main
class F {
  reformatThis() {
    return 1;
  }

  dontTouchThis(  ){
    return    2    ;
  }
}
```
